# Contributing

1. Open an issue for a substantial change; do not include personal content or credentials.
2. Fork the repository and create a focused branch.
3. Install requirements in a virtual environment. Use temporary data directories and synthetic fixtures.
4. Run Python tests, the Node chat-logic test, source checks, and the public-content audit from README.
5. Open a pull request describing the problem, final behavior, testing and material limitations. Include UI screenshots only with fabricated data.
6. A maintainer reviews the change. Passing CI does not merge a PR; security-sensitive code needs explicit review. Do not request secrets or privileged workflow execution for fork PRs.

Contributions are submitted under Apache-2.0. You retain your authorship. Do not contribute code, fonts, media or model files you cannot license. There is no CLA requirement in this preview.

Use ordinary language, accessible controls, visible error states and keyboard support. Preserve Persian/RTL functionality. Keep runtime data outside the source tree. Do not add telemetry, automatic model downloads, network exposure, automatic updates or expanded tool permissions without an explicitly reviewed design.

Maintainers may request changes or decline contributions. Independent forks remain allowed by the license; approval is required for the upstream repository, not for all downstream modifications.
